# Участие в разработке

Спасибо, что хотите помочь! Это русская адаптация [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search). Прочитайте этот файл до того, как браться за работу: он подскажет, куда ваш вклад попадёт лучше всего — сюда или в оригинал.

## Главное правило

**Этот репозиторий — шаблон под российский рынок.** Оригинал намеренно остаётся независимым от рынка и языка; этот форк, наоборот, существует, чтобы фреймворк хорошо работал для поиска работы в России и СНГ: порталы, язык, правила откликов, валюта. Отсюда простое разделение:

- **Всё, что специфично для РФ/СНГ или русского языка, — сюда.**
- **Всё универсальное — в оригинал.** Исправление в общей методологии, инструментах `tools/`, CI или безопасности полезно всем форкам; отправьте его в [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search) (сначала прочитайте [его CONTRIBUTING.md](https://github.com/MadsLorentzen/ai-job-search/blob/master/CONTRIBUTING.md)), и оно придёт сюда со следующим обновлением.

## Что принимается

- **Новые российские порталы.** Особенно ждём SuperJob (через API с ключом), Getmatch и другие сайты вакансий РФ/СНГ. Начните с `/add-portal` — он создаст навык по контракту порталов (см. ниже), а `/scrape` подхватит его автоматически.
- **Исправления перевода.** Опечатки, неестественные формулировки, калька, потерянный смысл правила при переводе, расхождения в терминах.
- **Адаптация под российскую практику.** Правила откликов на hh.ru и Хабр Карьере, оформление резюме, работа с зарплатой («на руки» / «до вычета НДФЛ»), источники зарплатных данных.
- **Исправления надёжности и корректности** — с продемонстрированным падающим случаем. Если ошибка есть и в оригинале, лучше отправить исправление туда.
- **Документация, закрывающая реальные пробелы**: настройка на конкретных платформах, устаревшие ссылки.

## Что не принимается

- **Личные данные профиля.** Шаблон поставляется с плейсхолдерами; ваш заполненный профиль живёт в вашей копии. CI это проверяет (`placeholder-integrity`).
- **Порталы, которые нарушают правила площадки.** Например, поиск по hh.ru в обход закрытого API или `robots.txt`. Порталы за авторизацией тоже не подходят.
- **Порты на другие агентные среды и дублирующие источники процесса.** Markdown-спецификации И ЕСТЬ реализация; вторая копия (под другой агентный CLI, слой оркестрации, команда-обёртка) расходится с первой, как только меняется любая из них.
- **Инфраструктура «на всякий случай».** Сложность нужно обосновать существующей проблемой, а не возможной.
- **PR «всё в одном».** Одна задача — один PR. Объединённые изменения попросят разделить.

## Планка для новых команд

Основной жизненный цикл **завершён**: `/setup` → `/scrape` → `/rank` → `/apply` → `/interview` → `/outcome` → калибровка обратно в `/setup`, а вокруг — `/expand`, `/upskill`, `/add-template`, `/add-portal` и `/reset`. У каждого этапа реального поиска работы есть владелец.

Поэтому планка для новой команды высокая. Тест, по которому принимались существующие: **автоматизирует ли она что-то уже существующее во фреймворке, где легко ошибиться** (описанный механизм, который ничто не выполняет; данные, которые что-то пишет, но никто не читает)? «Полезно» и «возможно» — недостаточно. Новые команды общего назначения лучше предлагать в оригинал.

## Утверждения проверяются

Ревью здесь эмпирическое. Сообщения об ошибках воспроизводятся на основной ветке, прежде чем рассматривается исправление; «все тесты зелёные» проверяется на то, отличают ли тесты основную ветку от исправления. Ускорить ревью можно так:

- Опишите падающий случай и как его воспроизвести.
- **Воспроизводите на реальном пути, а не на сконструированном входе.** Тест, который падает до исправления и проходит после, необходим, но недостаточен: падающий вход должен быть таким, какой процесс реально производит, а не собранным в тесте вручную. Покажите сбой через путь, по которому код действительно идёт, — документированный вызов CLI, реальный ответ портала, настоящий файл данных, — а не синтетическое значение, переданное прямо в функцию. Исправление, единственная демонстрация которого — вход, никогда не попадающий в реальный путь кода, отклоняется, даже если его тест зелёный.
- Тесты CLI кладите в `.agents/skills/<name>/cli/tests/` (bun test, по возможности без сети); тесты Python-инструментов — в `tests/`.
- Запустите то же, что запускает CI: `python3 tools/lint_skills.py`, `python3 tools/check_framework_version.py`, `python3 tools/security_guards.py`, `python3 -m unittest discover -s tests`, а в затронутых CLI — `bun run typecheck` + `bun test`.

**Правило упоминаний:** изменение, включающее ваш код, получает трейлер `Co-authored-by`; изменение, написанное независимо по вашему наблюдению или сообщению, упоминает вас в сообщении коммита и PR.

## Практические заметки

- **Контракт навыка портала**: команды `search`/`detail`, `--format json|table|plain`, ошибки в stderr в формате JSON с кодом выхода 1, повтор с задержкой на 429/5xx, по умолчанию никаких зависимостей времени выполнения. См. спецификацию `/add-portal`; образцы реализации — `habr-search` и `freehire-search`.
- **Границы личного использования**: навыки порталов, работающие с источниками, условия которых ограничивают автоматический доступ, несут заметное предупреждение «только для личного использования», а CI намеренно не делает живых запросов к порталам. Не «чините» это.
- **Изменения LaTeX**: оба шаблона должны собираться (`lualatex` для резюме, `xelatex` для письма) и сохранять точное число страниц, в том числе с текстом на кириллице. CI это проверяет smoke-сборкой.
- **Перевод**: соблюдайте единый словарь терминов (вакансия, резюме, сопроводительное письмо, оценка соответствия, стоп-фактор и т. д.); не переводите команды, флаги, пути, JSON-ключи, плейсхолдеры `[ВСЕ_ЗАГЛАВНЫЕ]` и машинные значения (статусы трекера, вердикты `PASS`/`FAIL`/`FLAG`).
- **PR из вашей копии.** Открывая PR из форка, проверьте выпадающий список «base repository»: GitHub по умолчанию предлагает upstream, и персональные данные легко отправить не туда.

Делаете форк под другой рынок или язык? Расскажите о нём в обсуждении [Community forks & adaptations](https://github.com/MadsLorentzen/ai-job-search/discussions/78) оригинального репозитория.

Вопросы и предложения — в [Issues](https://github.com/spichkinevgeniy/ai-job-search-ru/issues) этого репозитория: короткое обсуждение идеи ничего не стоит и может уберечь от работы не в ту сторону.
